# ModelPort 故障排查

适用：v0.1 · 第一阶段草稿 · 2026-10-15

先看“同步任务”中的最后一条消息，再看“运行记录”和 Chrome 对应页面。判断保存是否完成时，以目标平台实际内容为依据；不要因为进度条到达 90% 就重新建任务。

## 按现象处理

| 现象 | 检查与处理 | 判断恢复的依据 |
| --- | --- | --- |
| 双击 `start.cmd` 没出现窗口 | 从完整项目目录启动；缺少依赖时按[快速开始](quick-start.zh-CN.md)安装。若已有窗口，检查是否被最小化 | 出现 ModelPort 主窗口 |
| 提示工作空间已在另一个进程打开 | 检查是否已开着另一份 ModelPort，正常关闭旧实例后再打开；不要直接删除 `.data` | 正常进入原有模型库 |
| 未找到 Chrome 远程调试端点 | 确认使用标准安装位置的 Chrome 稳定版，在 `chrome://inspect/#remote-debugging` 启用远程调试；如浏览器要求重启，按提示完成 | “平台与账号”显示“已连接” |
| 连接等待，没有授权弹窗 | 查看 Chrome 是否已有待处理的连接请求；没有弹窗不一定失败，先看工具是否已连接。不要连续点击连接按钮 | 显示“已连接”，而不是以是否出现弹窗判断 |
| 连接被拒绝或超时 | 保留具体错误，确认 Chrome 已运行及调试设置；从原项目启动最新工作台后重新连接。不要直接扩大为允许所有调试来源 | 连接成功，错误不再出现 |
| “已连接”但平台仍要求登录 | 在“平台与账号”打开相应站点，在同一 Chrome 配置中正常登录或完成验证 | 对应站点显示正确账号 |
| 按钮操作提示“不支持的操作” | 当前连接按钮已修正为 POST 请求。若仍出现，记录具体按钮，确认不是旧窗口或旧目录里的应用；没有正在保存的任务时再正常重开 | 对应按钮操作正常 |
| 模型变为“待补充” | 打开“管理资料”查看具体提示；检查登录、说明、配置份数和下载文件 | 缺失项目补齐，预览不再显示对应阻止项 |
| 旧版本提示“未读取到模型标题”但浏览器中能看到标题 | 更新到 0.1.1 后重新读取。已修正只查找 h2 的问题，支持当前 div 标题并等待标题与详情就绪；不应直接断定需要重新登录 | 读取到与源站一致的模型名称 |
| 多配置链接未全部解析 | 0.1.1 支持通过可见配置卡片逐份切换并读取 ID。将源站份数与本地逐份对照，再尝试“重新读取来源资料”；仍缺失时按实际错误检查列表加载状态 | 每份必要配置都有对应文件，喷嘴等参数与源站一致 |
| 下载 3MF 失败或被浏览器拦截 | 查看 Chrome 下载提示和源站登录状态；按浏览器正常流程处理。已有原始文件时，可选择本地文件补充 | 打印配置记录显示文件名和大小 |
| “创想云封面需选择并确认实拍照片” | 选择真实拍摄的图片，设置用途为“实拍照片”，勾选“作为封面”，再“保存资料” | 重新预览可通过封面检查 |
| 因图片用途未知而无法开始 | 检查所有图片，不只是封面，分别选择实拍、渲染或说明／示意用途 | 没有“用途待确认”的图片 |
| NexPrint 停在上传控件初始化 | 这时还没有向站点发送模型文件。查看 Chrome 页面是否加载完成、是否有登录提示；不要将此阶段理解为大文件正在传输 | 日志出现“已通过 NexPrint 上传入口选择模型文件” |
| NexPrint 停在文件上传／解析 | 同时看站点是否出现文件卡片、解析按钮或上传进度。浏览器选中了文件并不等于网站已经接收 | 平台完成解析后进入“填写模型资料” |
| NexPrint 停在封面裁剪 | 正常情况下脚本会等待“好的”出现、点击并等待弹窗关闭。若仍失败，保留截图和“等待并确认封面裁剪弹窗”这一步的日志 | 裁剪关闭，日志进入“上传 NexPrint 模型图片” |
| `locator.click`／`locator.check` 超时 | 仅凭超时文本无法确定原因。查看最后步骤、截图及遮挡弹窗，保存完整报错供定位；不要连续强点页面 | 该步骤由脚本正常通过，不能只以手工补点成功作为修复证明 |
| 源许可已识别，但目标许可映射停止 | NexPrint 当前仅实现 Standard 的自动问卷映射；其他许可或变化后的选项需要核对。不要随意更换源许可 | 目标最终许可与实际源许可一致 |
| 资料修改后旧任务不能保存 | 重新准备表单，再核对保存；旧截图对应修改前的内容 | 新表单内容与本地当前资料一致 |
| “准备页面已关闭”或应用已重启 | 旧表单不再可靠。先查看平台是否已有作品，再重新准备 | 新表单打开且当前内容已核对 |

## 保存结果不明确时

出现“保存结果待核对”“未取得明确保存证据”或相似消息时，先停止重复保存。

1. 打开目标平台的模型列表或草稿箱，查找本次作品。
2. 如果已有作品，打开检查文件、内容、时间和可见性；在 ModelPort 的“处理 / 重试”中填写作品链接，点击“记录已有作品”。该按钮记录你的核对结果，不会重新上传。
3. 如果确认没有产生作品，在同一窗口勾选已检查确认项，再点“重新准备”。
4. 如果仍不能确定，保留现有记录和截图继续排查，不要用删除任务来代替平台核对。

NexPrint 当前按标题核验草稿。同名旧作品可能造成混淆，必须打开内容确认；创想云则要同时核对“只对自己”和保存后的详情页。

## 想重新跑一遍同步时

- **排队中／准备中**：先取消、中断，或“中断并删除”，等待操作结束。
- **失败／需要处理**：修正明确原因后，可在原任务中“处理 / 重试”。
- **已中断**：回模型库重新选择作品并预览同步。
- **想清理旧记录**：点击“删除任务”，选择放入回收站或彻底删除。仅回收站内的记录可恢复；彻底删除不删除模型库的素材或平台作品。
- **保存中**：等待结果核验，当前不能中断或删除。

删除本地记录不会撤销平台作品。此前已经保存过的作品，重新同步可能产生第二份草稿或私密模型。

## 提供哪些信息便于定位

从界面记录：模型链接、目标平台、最后执行步骤、完整报错、截图，以及当时是否手动点击了平台页面。一次记录一个任务，避免混用不同轮次的截图。

本地可查阅：

| 文件／目录 | 内容 |
| --- | --- |
| `.data/state.json` | 模型、任务与最近运行记录 |
| `.data/evidence/` | 来源、准备表单、失败和保存结果截图 |
| `.data/desktop-main.log` | 桌面启动和页面加载信息 |
| `.data/electron.log` | Electron 运行日志，具体内容取决于本次运行 |

这些文件可能包含个人模型信息、账号标识和页面内容。分享故障材料时按问题截取必要部分，不要把整个 Chrome 配置目录当作日志发送。

## 本版 NexPrint 两个已定位问题

本次排查确认过两处脚本时序问题：上传控件尚未初始化就设置文件，以及封面裁剪弹窗尚未出现就跳过确认。当前代码已改为通过真实文件选择器确认上传控件可交互，并等待裁剪弹窗出现、确认和关闭。

单配置风神像模型已完成一次无人工补点的上传和表单准备验证，停在“待确认保存”。这不能替代第二阶段对其他模型、多配置、许可及完整保存路径的验证，也不能保证平台改版后仍然无需调整。
